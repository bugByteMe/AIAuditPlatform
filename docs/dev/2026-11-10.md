# 2026-11-10

## Upload completion response latency

- Changed prepared-file visibility retry from a separate two-second allowance
  per file to one two-second deadline shared by the complete manifest. Folder
  uploads can no longer accumulate roughly two seconds of retry latency for
  each file exposed incrementally by shared storage.
- Kept successful staging deletion in the bounded garbage collector and moved
  successful-upload audit recording there as well. Once the atomic commit is
  durable, the status request returns `committed` without waiting for NFS
  cleanup, a remote-worker purge, or audit bookkeeping.
- Added regressions for manifest-wide retry timing and for keeping staging
  cleanup and audit callbacks off the committed response path.
