# 2026-09-22

- Allowed administrators to create account invitations with a concurrent-session limit of zero. Zero is preserved by the API and blocks new login sessions; the admin form and regression tests now cover the value.
- Allowed a group's concurrent live-run limit to be set to zero, which pauses admission of new runs. Backend validation, admin display and prompt handling, design notes, and regression coverage now preserve zero correctly.
- Replaced the admin account page's serial per-user MicuAPI balance requests with paginated token-list refreshes matched by token ID. Missing tokens and provider failures retain cached balances while surfacing an unavailable status.
- Made invitation registration concurrency-safe and retryable by coordinating invitation/username activation, retaining a private invitation digest, reusing registration sessions, and atomically enforcing session limits. Interrupted activation no longer deletes a provisioned MicuAPI token, and zero-session accounts activate successfully without receiving a login token.
- Added an activation-button busy animation and duplicate-submit guard. Post-registration workspace loading failures are now reported separately from activation failures.
