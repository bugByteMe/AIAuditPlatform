# Development notes - 2026-10-28

## OIDC HTTP connection and service-token reuse

- Reused one thread-safe `httpx.Client` across OIDC, central identity, and
  Keycloak administration requests so successive identity checks retain their
  HTTP connection pool instead of creating a client per request.
- Cached the Keycloak administration service-account token until shortly before
  its reported expiry. Concurrent administration calls share one token fetch.
- Invalidated and refreshed the cached service token once when Keycloak rejects
  an administration request with HTTP 401.
- Closed the shared identity HTTP client during ASGI shutdown.
- Added focused tests for persistent-client routing, concurrent token reuse, and
  the unauthorized-token retry path.
