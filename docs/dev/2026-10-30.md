# 2026-10-30

## Live chat workspace links

- Fixed new assistant messages whose workspace file destinations used
  `sandbox:/workspace/`, `file:///workspace/`, Markdown angle brackets, or safe
  unescaped spaces. These forms now normalize to the same authenticated
  workspace download action as historical `/workspace/` links.
- Kept normalization restricted to the `/workspace` root. Traversal, malformed
  encoding, backslashes, unrelated sandbox/file paths, and unsafe schemes remain
  non-clickable.

## Fine-grained workspace visibility

- Added private, selected-group-member, and whole-group workspace visibility.
  New workspaces default to private, while legacy shared workspaces migrate to
  whole-group visibility.
- Added stable account-ID grants, owner/admin access-management APIs, creation
  and management member pickers, visibility badges, and audit details for grant
  changes.
- Authorized selected and whole-group collaborators to upload and delete files
  as well as browse, download, chat, and fork. Workspace rename/deletion,
  access management, and exclusive run-lock changes remain owner/admin-only.
- Account group moves remove their grants; owner moves also reset owned
  workspaces to private and clear workspace grants. Account deletion/disable
  removes grants, and group renames propagate to workspace labels. Forks remain
  private and do not inherit grants.
- Prevented delayed run checkpoint writes from restoring stale visibility or
  group metadata after an access or membership change.
- Added focused backend access-control coverage and updated upload/frontend test
  fixtures. Tests were not run on this machine at the user's request.

## Hierarchical workspace view

- Added a nullable display parent to workspace persistence, summaries, details,
  empty creation, resumable creation uploads, and workspace updates while
  retaining `sourceWorkspaceId` solely for fork provenance.
- Added owner/admin-only hierarchy validation for visible same-group parents,
  cycle prevention, child promotion on deletion, and cross-group cleanup after
  owner moves. Forks inherit the source's parent only when it remains valid in
  the fork owner's group.
- Replaced flat workspace cards with cycle-safe nested rendering inside existing
  administrator group sections. Top-level branches start open, second-level
  branches start closed, manual fold overrides survive rerenders, and search
  includes and expands visible ancestor context.
- Added parent selectors for creation and later moves plus focused persistence,
  lifecycle, upload, hierarchy, search-context, and default-fold tests. Tests
  were not run locally per the existing constraint.
- Allowed workspace action menus to extend outside administrator group boxes so
  all options remain visible near a group's lower edge, and raised open menus
  above neighboring workspace rows.

## Keycloak display names

- Added optional `display_name` UserInfo synchronization into the existing local
  `displayName` profile field on login and periodic session revalidation, keyed
  by the immutable OIDC subject and username.
- Preferred display names in the signed-in user label and administrator account
  list while retaining usernames as secondary identity text and search terms.
- Documented the Keycloak user-profile attribute and protocol mapper. Added
  focused backend and frontend coverage; tests were not run locally per the
  existing constraint.
- Added presentation-only `ownerDisplayName` and `createdByDisplayName` API
  fields. Workspace and chat ownership remains stored and authorized by the
  immutable `owner` and `createdBy` usernames; the UI falls back to those names
  when a display name is unavailable.
